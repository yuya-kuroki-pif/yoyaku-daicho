# 予約台帳 / Sổ đặt bàn

飲食店向けのタブレット・スマホ用予約台帳アプリです。操作方法はトレタ、UIデザインはdinii予約台帳を参考に作成しています（白基調・青アクセント・左サイドバー・未配席行）。
Ứng dụng sổ đặt bàn cho nhà hàng, tối ưu cho máy tính bảng và điện thoại.

## トレタ風の操作方法 / Thao tác kiểu Toreta

| 操作 | 方法 |
| --- | --- |
| 予約を入れる | タイムテーブルの**空きマスをタップ** → その場にポップオーバーが開き、**人数（1〜8名）をタップ**すると時間・テーブル・人数が入力済みの登録画面が開く |
| 時間枠・複数席の選択 | 空きマスを**長押ししてそのまま横・縦になぞる**（PCはドラッグ）と、時間枠×複数テーブルを範囲選択できる（30分単位・青いハイライト表示）。指を離すとポップオーバーが開き、選択範囲が予約・ウォークイン・ブロックすべてに適用される |
| 複数卓の表示 | 複数テーブルにまたがる予約・ウォークイン・ブロックは、連続する行を**縦に結合した1つの枠**で表示（離れた卓は枠が分かれる）。ドラッグすると全卓まとめて平行移動する |
| ウォークインを入れる | 空きマスをタップ → ポップオーバーで**「ウォークイン」タブ → 人数をタップ**で、その場で「来店中」として即時登録 |
| 予約の詳細・編集 | 予約ブロックを**タップ** |
| 配席移動・時間変更 | 予約ブロックを**長押し**（PCはドラッグ）→ 別のテーブル・時間へドラッグ（15分単位でスナップ、移動先の時刻をゴーストで表示） |
| 滞在時間の変更 | ブロックの**右端ハンドルをドラッグ**して伸縮 |
| 未配席の予約を配席 | 最上段のピンクの**未配席行**からテーブル行へドラッグ（逆方向で割当解除） |
| 予約ブロック | 空きマスをタップ → ポップオーバー下の**「🚫 ブロック」**でその席・時間帯（2時間）を封鎖。ネット予約の空席在庫から自動除外されます（斜線ストライプ表示、タップで解除、ドラッグ/右端で範囲変更可） |
| 来店・会計処理 | リスト表示の「来店」「会計」ボタン、または編集画面のステータスボタン |

予約ブロックはdinii風の色分けです: 白＝予約、薄緑＝コース付き予約、濃紺＝来店中、グレー＝退店済、赤＝ノーショー、赤点線＝未配席。ブロック内に来店回数（n回／初回）チップと🍴コースアイコンを表示します。

ダブルブッキング（同じテーブルで時間が重なる予約）になる場合は警告を表示します。

## 機能 / Tính năng

- **タイムテーブル / Lịch bàn** — テーブル×時間のグリッドで予約状況を一覧表示。現在時刻の赤いラインを表示します。
- **リスト / Danh sách** — 当日の予約を時間順に一覧表示。「来店」「会計」ボタンでステータスをワンタップ更新できます。
- **顧客台帳 / Sổ khách hàng** — 電話番号ベースで来店回数・最終来店日を自動集計。名前・電話番号で検索できます。
- **新規予約 / Đặt bàn mới** — 日付・時間・滞在時間・人数（大人/子供）・名前・フリガナ・電話・テーブル・コース・メモを登録。同じテーブルの重複予約は警告します。
- **ウォークイン / Khách vãng lai** — 飛び込み来店をワンタップで「来店中」として登録。
- **ステータス管理** — 予約 → 来店中 → 退店済 / ノーショー / キャンセル。
- **テーブル設定 / Cài đặt bàn** — テーブルの追加・削除・席数変更・**グループ設定**（ホール／カウンター／個室など。タイムラインにグループ見出し行を表示）、営業時間の変更。
- **結合テーブル（合席） / Ghép bàn** — テーブル設定の「結合テーブル」で、組み合わせる卓と合計の最大人数を設定（初期例: T1+T2で8名まで）。1卓に入らない人数のネット予約は、結合テーブルが全卓空いていれば自動で複数卓を確保します。チャットでも「T1とT2を合わせて8名まで」「T1とT2の結合を解除」で設定可能。
- **チャット操作 / Trò chuyện** — サイドバーの「チャット」から日本語（一部ベトナム語）の指示で台帳を操作できます。例:「明日19時 田中様 4名 T3で予約」「ウォークイン 2名 C1」「田中様の予約をキャンセル」「田中様 来店／会計」「T2を19時から2時間ブロック」「T1を6席に変更」「T1をホールグループに」「営業時間を17時から23時に」。※オフラインで動くパターン解析のため言い回しは例に近い形が確実です。
- **予約サイト・在庫連携 / Trang đặt bàn** — 予約サイト（経路）の登録・受付ON/OFF・色・連携テーブルを設定。台帳の予約状況から各サイトの空席在庫（30分刻み・滞在2時間想定）を自動計算し、満席の時間帯は×表示。在庫マスをタップするとそのサイト経由の予約を登録できます。予約には「予約経路」を記録でき、タイムラインのブロックにサイト色のドットが表示されます。
- **自社予約サイト（グルメサイト風の店舗ページ） / Trang đặt bàn của cửa hàng** — 予約サイトは食べログ風の店舗ページです。ヘッダーに店名・よみ・Google評価・口コミ件数・ジャンル・最寄り・予算（夜／昼）・定休日・「ネット予約可」バッジ、タブは「トップ／メニュー・コース／写真／口コミ／地図・店舗情報」。トップは写真カルーセル → 店舗基本情報 → ネット予約パネル（来店日をタップしてカレンダーから選択 → 人数 → 空きのある時間を選び「予約する」） → お店の紹介 → メニュー・コース → 口コミ → 写真 → 店舗情報（詳細） → 地図の順に並び、PCでは右カラムに空席確認・予約と基本情報を固定表示します。店舗情報（詳細）は店名・ジャンル・予約・お問い合わせ・予約可否・住所・交通手段・営業時間・定休日・予算・支払い方法・席数に加え、個室・貸切・禁煙・喫煙・駐車場・空間・設備・ドリンク・料理・利用シーン・サービス・お子様連れ・ホームページ・公式アカウント・オープン日・備考（台帳の「店舗詳細」で入力した項目のみ）を表示します。コース（名称・料金・説明）は「コースマスタ」で登録します。
  - **口コミ・評価は Google マップから取得**: 台帳の「Googleマップ連携」に Place ID と Google API キー（Places API (New) を有効化、HTTPリファラー制限を推奨）を設定すると、予約サイトが Google から評価・口コミ（最大5件）・写真（最大10枚、投稿者名のリンク付きで表示）を取得して表示します（お客様のブラウザに6時間キャッシュ）。未設定の場合は Google マップへのリンクのみ表示します。あわせて住所・電話番号・営業時間・ジャンル・ウェブサイト・価格帯・支払い方法・駐車場・紹介文も取得し、台帳の「店舗情報」で空欄の項目は Google の情報で自動補完します（台帳の入力が優先）。テーブル設定の「Googleマップから店舗情報を取り込む」ボタンで、これらを入力欄に流し込んでから確認・保存することもできます。Place ID が分からない場合は「店名または Google マップのリンク」に入力して「Googleマップから取得」を押すと、候補から選ぶだけで Place ID の設定と店舗情報の取り込みが行われます。初期状態では Robata Naru-Charcoal Grill（ハノイ）の Place ID と店舗情報が設定済みです（API キーは公開しないため、端末ごとにテーブル設定で入力します）。
- **サイト別URL発行** — 予約サイト画面で、自社予約サイト・Instagram・Googleマップなどサイト（経路）ごとに専用の予約URL（`booking.html?site=〇〇`）を発行・コピーできます。Instagramのプロフィール・Googleマップ・自社HPに貼り分けると、どの経路からの予約かが自動記録されます。予約の流れは食べログ準拠です: 店舗ページのネット予約パネルで来店日（タップすると人数に応じた ◎ 空席あり／△ 残りわずか／× 満席／休 定休日 付きの月カレンダーが開く）→ 人数（その日に入れる人数だけ選択可、◎△× 付き） → 時間（空きのある時間だけ選択可、◎△ 付き）を選び「予約する」 → コース選択（「席のみ予約」または各コースの「予約する」。メニューの「予約する」から入った場合はそのコースで固定） → お名前・電話番号・メール・お子様の人数・ご利用目的・ご要望を入力し注意事項に同意 → 確認画面で「予約を確定する」。予約時に**予約番号**が発行され、「予約の確認・キャンセル」タブから電話番号＋予約番号で内容確認とキャンセルができます（キャンセルは台帳にも即時反映）。内容は台帳に「予約」として自動反映され、未確認バッジが表示されます。受付停止・予約可能席・定休日は各サイト／台帳の設定に連動。台帳の「店舗情報」設定（店名・電話・住所・注意事項）を予約サイトに表示します。日本語・ベトナム語対応。
  - 注意: データはブラウザ内保存のため、お客様のスマホなど**別の端末から開いた場合は店舗の台帳に届きません**。他端末からの本格運用にはサーバー（Supabase等）が必要です。
- **月間カレンダー / Lịch tháng** — 月ごとの予約状況（日別の組数・人数・未確認件数・定休日）を一覧表示。日付をタップするとその日のタイムラインへ移動します。
- **予約検索・絞り込み / Tìm kiếm** — 予約一覧で名前・電話番号による全期間検索と、ステータス（未確認／予約／来店中／退店済／ノーショー／キャンセル）での絞り込みができます。「印刷」ボタンで一覧を印刷できます。
- **ネット予約の未確認バッジ** — 予約サイトから入った予約は「NEW」表示になり、画面上部に未確認件数のバッジが出ます。バッジをタップすると未確認一覧に移動し、「確認済にする」または来店処理・編集保存で解除されます。
- **顧客情報の自動入力** — 予約フォームで電話番号を入力すると、過去の予約からお名前・フリガナ・会社名・メールアドレスなどを自動で反映します（来店回数も表示）。
- **予約の複製** — 編集画面の「複製」で、同じお客様情報・内容の新規予約を作成できます。
- **席数超過の警告** — 人数が選択したテーブルの席数を超える場合は、保存前に警告します。
- **定休日・臨時休業日 / Ngày nghỉ** — テーブル設定で曜日と個別の日付を設定。タイムラインに定休日バナー、カレンダーに「休」マークを表示し、ネット予約サイトは定休日の受付を自動で停止します。
- **コース・タグのマスタ管理** — テーブル設定でコース名・タグ名を追加・変更・削除できます。
- **バックアップ・復元・CSV出力** — テーブル設定から全データのJSONバックアップ保存・復元、予約全件のCSV出力（Excel対応・BOM付き）ができます。
- **DMスクリーンショットから予約（画像読み取り）** — チャット画面にお客様とのDM（Instagram・LINE等）のスクリーンショットを貼り付け（Ctrl+V）・📷で添付・ドラッグ＆ドロップすると、Claude（Messages API の画像入力、モデル `claude-opus-5`）が日時・人数・お名前・電話番号・コース・ご要望・媒体を読み取り、結果カードの「予約フォームで確認して登録」で内容を確認してから登録できます。テーブル設定の「画像読み取り」に Anthropic の API キーを設定してください（ブラウザから直接呼び出すため、利用上限を設定したキーを推奨）。画像は長辺1600pxに縮小して送信し、端末には保存しません。
- **複数店舗の切替 / Nhiều cửa hàng** — 台帳のデータは店舗ごとに分けて保存されます。画面上部のセレクトで店舗を切り替え、「＋ 店舗を追加…」で新しい店舗（空の台帳）を作成できます。テーブル設定の「店舗の切替・管理」から店舗の削除も可能です。予約サイトのURLは `booking.html?store=〇〇&site=〇〇` の形で店舗ごとに発行されます。
- **日本語 / ベトナム語切替** — 画面右上のボタンでいつでも切替できます。
- **スマホ対応** — 画面幅が狭い端末では下部タブナビゲーションとフローティングボタン（＋新規予約 / 🚶ウォークイン）に切り替わり、登録画面はボトムシート表示になります。

## 使い方 / Cách sử dụng

ビルド不要・依存なしの静的Webアプリです。データはブラウザの localStorage に保存されます。

```
# 任意の静的サーバーで配信（例）
python -m http.server 8210
# → タブレットのブラウザで http://<PCのIPアドレス>:8210 を開く
```

`index.html` をブラウザで直接開いても動作します。

## クラウド保存（Supabase）

接続先を設定すると、台帳のデータが Supabase（PostgreSQL）に保存され、ログインした全端末と予約サイトで共有されます。未設定なら従来どおり端末内保存で動きます。

1. https://supabase.com でプロジェクトを作成します（リージョンは店舗に近い場所、例: Singapore / Tokyo）。
2. ダッシュボードの **SQL Editor** で [`supabase/schema.sql`](supabase/schema.sql) の内容を実行します（テーブル・行レベルセキュリティ・予約サイト用の関数を作成）。
3. **Authentication → Users** でスタッフ用のユーザー（メール＋パスワード）を作成します。**Authentication → Providers → Email** で「Confirm email」を無効にすると、作成したユーザーがすぐ使えます。サインアップは無効のままにしてください（スタッフ以外がアカウントを作れないように）。
4. **Project Settings → API** の Project URL と anon public キーを [`public/config.js`](public/config.js) に設定して公開します。
5. 台帳を開くとログイン画面が出ます。初回ログイン時、クラウドが空であれば端末内のデータを移行するか確認されます。

仕組み: 店舗ごとの設定は `stores` テーブルの JSON、予約は `reservations` テーブルに1件1行で保存し、変更分だけを書き込みます。他端末や予約サイトからの変更はリアルタイムで台帳に反映されます。予約サイト（お客様）はテーブルに直接アクセスできず、`booking_*` 関数経由で空席計算・予約作成・予約番号での確認／取消だけができます（氏名・電話番号は取得不可）。予約作成時はサーバー側でも受付状態と同じ卓の重複を検証します。Claude API キーはクラウドへ送らず端末内に保存します。

## セキュリティ上の配慮

- 画面に表示する文字列はすべてエスケープし、外部（Google マップ・Claude）から受け取った URL は http(s) 以外のスキームを捨てます。
- 各ページに Content Security Policy（スクリプトは自サイトのみ、通信先は Google Places API と Anthropic API のみ）を設定しています。
- CSV 出力では先頭が `=` `+` `-` `@` の値に `'` を付け、表計算ソフトでの数式実行を防ぎます。
- お客様・スタッフの入力には文字数の上限を設け、バックアップの復元は構造とサイズ（10MB）を検証します。予約番号は暗号論的乱数で生成します。
- API キーはソースコードに含めず、端末ごとにテーブル設定で入力します（Google のキーは参照元ドメインと API を制限したものを使用）。
- **端末ロック（PIN）**: テーブル設定で PIN を設定すると、台帳を開いたとき・一定時間操作がないとき・画面を離れたときに PIN を求めます（5回失敗で待ち時間）。有効時は Claude API キーを PIN 由来の鍵（PBKDF2 + AES-GCM）で暗号化して保存し、ロック解除中だけメモリ上で使います。
- **費用の上振れ防止**: 画像読み取りは1日あたりの回数上限（既定50回）を設定できます。Google Cloud 側では月額予算アラートを設定しています。
- **データ消失対策**: 7日以上バックアップを保存していないと台帳上部に催促を表示します。予約サイトは最新データに予約を追加するだけで、台帳の設定を上書きしません。Supabase を使う場合はデータがクラウドに保存され、Supabase 側の自動バックアップも利用できます。

## 注意

- データは端末（ブラウザ）ごとに保存されます。複数端末での共有にはサーバー側のデータベースが必要です。ブラウザのデータ削除で消えるため、テーブル設定の「バックアップを保存」で定期的にバックアップを取ってください。
- 初回起動時にサンプル予約が入っています。不要な場合は削除してください。
